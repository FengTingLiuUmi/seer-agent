## 1. 因子系统与脚本是怎么工作的

### 1.1 「因子」是什么
「因子」是赛尔号的逐关 PVE 副本玩法，每个因子精灵对应一条**多关挑战线**（通常 5 关，第 1~5 关难度递进），通关掉落精灵/升阶材料。版块按三档难度分区：

| 难度 | 主题数 | 典型特征 |
|---|---|---|
| 简单 | 52 | 低配强攻秒杀，7 只以内常驻精灵通用垫底 |
| 困难 | 135 | 需要针对个别 Boss 特性微调出招/数值 |
| 地狱 | 781 | 必须逐关读 Boss 特性、多套方案、精确配装 |

> 难度中文 ⇄ SeerAPI：**简单=easy / 困难=normal / 地狱=hard**（本体的 `pve:difficulty` 用受控词表，中文作 label、英文作 SeerAPI 值）。

### 1.2 脚本 = 「出招表」的自动化
雷小伊登录器（脱机版）把「每回合让谁上、放哪个技能、什么时候换人/嗑药」自动发包执行。帖子分享的文件有四种（**【论坛·thread-124】**）：

| 格式 | 含义 |
|---|---|
| `.afc` | 对战方案文件：出战/切换/出招/嗑药/套装称号/绿火/压血 |
| `.afcs` | 因子配置包：`.afc` + 因子关设置（整条防线的导入包） |
| `.ysc` | 纯自定义脚本：只含发包与说明（用内置打法时不报异常也能分享） |
| `.yscs` | 自定义脚本 + 对战方案整合包（自定义打法时用） |

所以「看脚本为什么这样打」本质是看这份**逐回合出招表**：每一手（换人 → 先手 → 叠 Buff → 强攻/磨血/弹伤）背后都是对 Boss 机制的应对。

### 1.3 一条脚本里反复出现的「可调项」及其作用
- **套装**：漆黑 / 银翼套 / 耀世 / 勇者 / 未来 / 典狱长 —— 决定输出或防御侧的整体加成。
- **称号 / 眼镜**：假面 / 神话 / 洛林卡之星 —— 叠在套装之上的增伤/减伤/暴击。
- **火**：绿火（自动放）、金火（借用火焰类增伤，帖子里叫「借金火」）、星星领火。
- **珠子 / 全面提升药水**：临时面板/暴击/固伤道具（低配帖强调「不磕珠子不嗑药」= 平民可复现）。
- **压血 / 压攻 / 压防 / 定格 / 爆攻 / 防体 / 特防体**：把精灵面板调到满足 Boss 阈值或触发自身魂印的精确数值。
- **扫荡**：通关概率低时改为自动扫荡「赌」，挂机睡觉也能出。
- **防掉线**：脱机挂机时避免长时间运行被踢，影响挂机时长。

## 2. 核心套路：为什么「这样打」

因子 Boss 大多靠**特性机制**（消强/偷强、每回合固伤、裸伤上限、吸伤回血、护盾、控场、随机弱化等）逼你放弃「无脑高伤」，于是打法被归纳成几种固定套路。以下按「机制 → 为什么 → 常见表现」展开。

### 2.1 强攻（一击秒杀）
- **机制**：属性克制 × 满血/压血爆攻 × 增伤(套装/场地/判弱) → 一回合打穿 Boss，避免它活到第二回合触发机制。
- **为什么可行**：因子 Boss 血量固定（地狱约 1 万~1.8 万），只要单发伤害够高就能抢在 Boss 的「下回合固伤/偷强/控场」生效前结束战斗。「防掉线/挂机」也是因为流程短、可批量。
- **常见**：王哈（王·哈莫雷特）、圣普（圣灵谱尼）、艾欧丽娅、星光三主宠循环克制。（【论坛·thread-5977】标题点名「无圣普王哈」= 0 氪缺这两大强攻锚点，就要用三主宠/艾欧/幻境替代。）

### 2.2 送头 / 叠毒上 debuff（潘家族：火潘 / 草潘 / 冰潘）
- **机制（火潘）**：用「火潘」（潘克多斯 4344）**主动送死**，阵亡给 Boss 挂 5 回合「鬼火缠绕」（受攻击伤害 +50% 叠满 +150%，阶段结束吃自身攻击 50% 固伤），再上强攻手。
- **机制（冰潘）**：用「冰潘」（斯克鲁恩 4463）**送死**，给 Boss 挂「霜寒封印」——3 回合内防御/特防强化失效、无法用技能回血、每次用技能后受最大体力 10% 固伤（封顶自身攻击 200%）。
- **机制（草潘）**：用「草潘」（加尔鲁特 4606）**防体站场受击叠毒**，给 Boss 叠「碧叶猛毒」——每层使对手攻击伤害 -6% 且用技能后受 100 固伤，最高 12 层。
- **为什么**：地狱 Boss 普遍**免疫面板、偷强、裸伤上限**，单发直伤打不动 → 先送潘/叠毒把 Boss 挂上 debuff（增伤 / 封回血与强化 / 降伤+固定毒伤），后续强攻手伤害被放大、Boss 被持续放血。
- **魂印依据【已核实】**：火潘=潘克多斯魂印 1569（鬼火缠绕）；冰潘=斯克鲁恩魂印 1675（霜寒封印）；草潘=加尔鲁特魂印 1811（碧叶猛毒），三者均 boss 有效。
- **别名纠错**：「潘」家族真名都不含「潘」——火潘=潘克多斯(4344)、草潘=加尔鲁特(4606)、冰潘=斯克鲁恩(4463)；绝非潘多拉(2518)/灾厄潘多拉(2965,3396)。

### 2.3 站场 / 磨血（坦克慢慢磨）
- **机制**：当 Boss **免疫高伤并转体力** 或 **面板免疫** 时，用高防/高特防 + 回血精灵站着慢慢打。
- **为什么**：话术「卡裸伤」= 把单发伤害压在 Boss 的「裸伤 >X 就吸收」阈值以下，让它回不上血、磨不死你，再靠每回合小伤 + 自愈磨死它。
- **常见**：卡莎（特防体）、村长（防御定格 336、体力 799~935）、丽莎（特防体）、眠酱（攻体）、草潘（防体站场叠毒）、草王（小草王送头套盾）。
- **实例【论坛·thread-3313 第二关】**：Boss「免疫裸伤>2000并转体力」，所以方案是「卡裸伤村长站场」或「防体草潘站场」，而不是高伤强攻（否则等于给 Boss 白回血）。

### 2.4 弹伤 / 反伤（把 Boss 的伤害还回去）
- **机制**：让 Boss 打自己，把致死伤害以**固伤**形式反弹回去，或让队友先手削血再由核心反伤收尾。
- **为什么**：对付「开局给护盾/护罩、免疫高面板攻击」的 Boss —— 护盾挡直伤但挡不住反弹伤害，用反伤绕过护盾与免疫。
- **魂印依据【已核实】**：帝皇之御（表姐）「受到致死攻击后保留 1 点体力，并把该致命伤害以固伤形式反弹给对手」。
- **常见组合【论坛·thread-3313 第四关】**：「鲁斯王弹伤」= 三只波克尔 + 魔焰 + 鲁斯王：先用先制手（波克尔/魔焰）削血/逼出机制，鲁斯王负责把致命伤害弹回去。
- **铁律：反弹是一套方案，不是两套**（先手/后手只是两种实现，弹伤本体同一件事）。先手反弹未生效 ≠ 方案失败；**禁止据此直接跳后手反弹，更禁止改用户阵容/精灵**。应先定位未生效原因（自爆没放出、必先次数被抢、命中/封属/Boss免伤反弹、出场顺序、PP 等），在现有配置上修触发条件重试。只有①用户明确要求后手、或②关卡只允许后手（禁自爆/禁必先）才考虑；改阵容必须先获用户同意。

### 2.5 必先大队（先制集火抢节奏）
- **机制**：多只带「必先（先制）」技能的精灵轮番先手，把高攻 Boss 一轮打死，或抢在 Boss 控场/偷强前连续出手。
- **为什么**：对付「高概率**害怕**控场 / 每回合全属性+1 / 出手前偷强」的 Boss —— 只要我方全程先手，Boss 根本轮不到用它那套机制。
- **实例【论坛·thread-3313 第五关】**：Boss「高概率害怕控 + 偷强 + 每回全属性+1」，方案 2 是「火潘 + 蒂朵 + 西塔伦 + **必先大队**」。

### 2.6 场地增伤（蒂朵）
- **机制**：蒂朵按奇/偶回合登场，把场地变成「灵籁泳馆（必定命中 + 回合结束回 300 血）」或「星璨舞台（攻伤 +130% + 回 PP）」。
- **为什么**：某些 Boss 会躲闪/回血/免疫，铺「星璨舞台 +130% 攻伤」让后续强攻手一击必杀；铺「灵籁泳馆」解决命中与续航。
- **魂印依据【已核实】**（蒂朵）：奇数回合登场→灵籁泳馆（必中+回 300）；偶数回合登场→星璨舞台（攻伤+130%+回 PP）。

### 2.7 精确压属性 / 定格（数值阈值）
- **机制**：为满足「免疫面板超过 X」「免疫裸伤高于 Y」等条件，把面板**精确**调到阈值以下/以上。
- **为什么**：差 1 点防御/体力就可能触发 Boss 的免疫或把伤害卡进吸收区间。帖子里反复出现「防御定格 336」「体力 799~935」「鲁斯王压防（用铅白，别用圣战无限）」「爆攻压血」就是这类阈值话术。
- **实例【论坛】**：thread-4589「2.0 的鲁斯王最好**压防**，有条件的用**铅白**，别用**圣战无限**（防太高会触发某关对高防的惩罚/卡裸伤失衡）」；thread-3313 第二关「村长防御定格 336，体力 799~935」。

### 3.5 被 Ban 强者的替代思维
地狱因子常有「精灵 Ban」（不能用某几只）。thread-3313 直接 Ban「王哈 / 典韦 / 斯克鲁恩」，于是整条方案都用替代主义——
- **王哈被 Ban** → 用地王/魔钰/艾欧/张飞等其它强攻手补。
- **典韦、斯克鲁恩被 Ban** → 少了常用「先制强攻/回血站场」件，转为「必先大队 / 弹伤 / 场地」套路。

> 核心心法：**先看 Boss 特性，再看自己手里哪只精灵的「魂印/技能」恰好克制这条特性**，然后用套装/称号/压血把数值卡到位。帖子标题里的「无表 / 无潘 / 单表 / 三表姐 / 零氪无漆黑无限定」都是在描述「我手里没有哪些件，于是换成了什么」。

## 6. 完整实例拆解：伊塔回溯型地狱因子（thread-3313，无表多表方案）

这是版块里最规范的一类「Boss 特性 → 每关为什么这样打」样例，直接照抄其结构就是该版块的通用心法。

**Ban 列表**：王哈、典韦、斯克鲁恩。

| 关 | Boss（属性/血量） | 关键特性 | 方案 & 为什么 |
|---|---|---|---|
| 1 | 机械战斗 10000 血 | 5% 概率 5 倍伤（秒人）、消强、每回合 300 固伤、随机弱化我方三项 | **爆攻压血魔钰强攻**：抢在 5 倍随机触发前秒掉。备选**特防体丽莎站场**：高特防+回血扛住固伤和弱化慢慢磨。 |
| 2 | 机械超能 10000 血 | 免疫裸伤>2000 并转体力（回血）、消强、300 固伤、强化回血/月亮有效 | **卡裸伤村长站场（防御 336、体力 799~935）**：把单发压到 2000 以下，杜绝给它回血。备选**防体草潘站场**。绝不上高伤强攻。 |
| 3 | 机械火 12000 血 | 出手前偷强、每回合全属+1、消强、500 固伤、双防弱化 | **特防体卡莎站场（可换村长）**：高特防+回血对耗。备选**爆攻地王强攻**：地面克火，抢一手秒掉。 |
| 4 | 机械神秘 15000 血 | 免疫面板>100 的攻击、偷强、开局 5000 护盾护罩、500 固伤 | **鲁斯王弹伤（三波克尔+魔焰+鲁斯王）**：反弹绕过护盾。备选**攻体眠酱站场**。 |
| 5 | 机械 18000 血 | 出手前偷强、每回合全属+1、500 固伤、高概率害怕控 | **火潘+蒂朵+表姐+张飞+泰坦**：潘判弱→蒂朵铺增伤场地→表姐抗/反/减伤→张飞泰坦爆发。备选**火潘+蒂朵+西塔伦+必先大队**：全员先手，让 Boss 的害怕控场根本出不了手。 |

**这一条拆完能得到的通用命题**：
1. 「能秒就秒」优先级最高——省回合、防机制。
2. 「秒不掉」就看 Boss 是**吸伤/免疫高伤**（→站场磨）、还是**护盾/免疫面板**（→弹伤）、还是**控场/偷强**（→必先/判弱）。
3. 每个对策都配一套「强攻」+一套「站场/弹伤」双方案，因为同一套不一定稳。

### 属性克制倍率换算（用户定案，已用 type_multiplier.py 回验 8/8）
- **单 vs 单**：矩阵值 ∈ {2 克制 / 1 普通 / 0.5 微弱 / 0 无效}；0 倍=攻击方打不出攻击红伤，但**技能效果仍触发**。
- **恰一侧双属性**（拆成两个单-vs-单配对值 v1、v2）：均为 2→**4**；含 0→**(v1+v2)/4**；其余→**(v1+v2)/2**。
- **双 vs 双**：r1=攻对守属性1合成值、r2=攻对守属性2合成值；最终 = **(r1+r2)/2**。
- 单属性矩阵（26×26=676 条精确倍率）已灌进 `seer-typechart.ttl` / `seer-all.owl`；换算代码 `ontology/type_multiplier.py`。

## 9. 因子名对齐、伪因子剔除与精灵消歧（两源合并的约定）

### 9.1 因子名别名（论坛简称/错写 → B站规范名）
判据：① B站规范名与论坛名互为缩短形；② 关卡序列与血量一致；③ 异体字或笔误（亚/娅、茵/因、丽/莉、至/之、凤/凰、地/迪、轮/伦、赛/塞、奇/骑、伐/伏、原/元）。

映射表在 `scrape/factor_alias.json`（12 组，每组带依据），`build_final.py` 合表时按 `norm()` 去 `·` 与空格后套用。

- 典型：`战王 → 极战·阿尔斯兰`、`南霜 / 不破霜南帝 → 不破帝·南霜`、`东辉 → 天奔流·东辉`、`耀焰万象·文森特 → 曜焰万象·文森特`、`混灵莱茵哈特 → 混灵·莱因哈特`、`霜之荆棘蒙鲁特杜 → 霜之荆棘·蒙鲁特`。
- **不合并 = 特性全丢**：论坛「困难」档与 B站「地狱」档若挂在两个 factor 名下，会出现「同一因子一半有特性、一半没有」的假象。

### 9.3 精灵消歧流程（可复用）
1. 用 `seerapi list pet --offset/--limit 200 --fields id,name,type` 分页拉全量（4956 只）→ `scrape/pets-index.json`；TypeCombination 的 id → 元素映射取自本体（139 条，覆盖全部被引用的组合）。
2. 分级匹配：`exact`（去 `·`/空格后同名）> `sub`（令牌是精灵名的缩短形，安全方向）> `amb`（精灵名被塞进更长令牌，危险方向）> `fuzzy`（ratio ≥ 0.75）。
3. 人工 override：`scrape/pets-token-override.json`，accept 必附 `seerapiId` 与依据，reject 记理由。**判不了就不收。**
4. `ontology/build_supp.py` 生成 `seer-pve-supp.ttl`，**必须无条件写 `rdf:type` / `rdfs:label` / `seerapiId`**：它把 `seer-all.owl` 当输入，若用「已有 label 就跳过」判断，重入时会只剩 altLabel、label 全丢（已踩两次）。
5. 结果：581 个攻略令牌 → 528 个对回本体；本体精灵 167 → 343；剩下 53 个昵称/组合名/技能名如实留空。
