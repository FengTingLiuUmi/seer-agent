# 登录实现（2.0.9 反编译对照）

本文把 2.0.9 的关键函数与 `seer_rebuild/login.py`、`client.py` 一一对应。
函数地址来自 `.text`（镜像基址 `0x400000`），反编译文本见
`re/tools/ghidra_209x.log`（UTF-8 版本：`re/dumps/ghidra_209x_utf8.txt`）。

## 1. 函数表

| 地址 | 作用 | 关键证据 |
|---|---|---|
| `FUN_0040f897` | 账号密码鉴权 | 拼 `userIdentity/authenticate`，解析 `result/data.uid/data.session/err_desc` |
| `FUN_00651bf5` | OAuth code → token | POST `token/trans`，body `appid=20210906002&duid=<duid>&code=<code>` |
| `FUN_00419d21` | 取网关 | GET `online_gate?is_ssl=1`，最多 10 次，失败兜底 `123.207.217.117:3007` |
| `FUN_0040edc0` | 登录编排 | 无 session 先鉴权；`0x3eb/0x3ec` 特殊分支；成功后进入模式分发 |
| `FUN_0040eb73` | 模式分发 | `param==2` → `FUN_0041886b`；`1` → `FUN_0044ae52`；否则 `FUN_0044b723` |
| `FUN_0041886b` | Unity / H5 WSS | `wss://` + 网关，子协议 `taomee`/`h5_web_taomee`，发 cmd 1001 |
| `FUN_0044ae52` | Flash | 连服务器列表，发 cmd 1001 + `0x8ca151` 的 44B body |
| `FUN_0044b723` | H5 Web 模式 | `serverid` + `FUN_0044bfa2`，发 cmd 1001 |
| `FUN_0041a625` | 1001 响应处理 | `cmd==0x3e9` 且 `result<0x65` → 记录 uid、登录成功 |
| `FUN_0061c0e1` | 平台日志 | 根据模式输出 `Unity` 或 `Flash` |

## 2. 账号密码

`FUN_0040f897` 的 URL 拼接顺序（与 `login.authenticate` 一致）：

```c
"http://account-co.61.com/index.php?r=userIdentity/authenticate&callback=jQuery19008830978978300397_"
+ "&account=" + account
+ "&rememberAcc=false&passwd=" + md5(password)
+ "&rememberPwd=true&vericode=" + ...
+ "&game=02&tad=none&_=" + random
```

返回 JSON/JSONP 后：

```c
result = json["result"];
if (result == 0) {
    uid = json["data.uid"];
    session = json["data.session"];   // 32 hex 字符
} else {
    err = json["err_desc"];
}
```

**2.0.9 的细节**：session 长度 `>0x1a` 时截到 `0x20`（32 hex 字符）。
本仓库 `authenticate()` 做了同样截断。

## 3. OAuth → token

2.0.9 的 `FUN_00651bf5`：

```c
body = "appid=20210906002&duid=" + duid + "&code=" + code;
POST "https://account-co.61.com/v3/?r=token/trans"
headers:
  Accept: application/json, text/javascript, */*; q=0.01
  Accept-Encoding: deflate, br
  Accept-Language: zh-CN,zh;q=0.9
  Content-Type: application/x-www-form-urlencoded; charset=UTF-8
```

返回 token 文本。授权页 URL 在 `0xb84242` 起：
`https://account-co.61.com/v3/?r=...&appid=20210906002&scope=userinfo&...&redirect_url=...authorization%2Fsuccess&state=...`

## 5. 三种连接模式

| 模式 | 2.0.9 函数 | `DAT_00e68fd8` | 本仓库 `GameClient(mode=...)` |
|---|---|---|---|
| H5 Web | `FUN_0044b723` | `0` | `h5` |
| Flash | `FUN_0044ae52` | `1` | `flash` |
| Unity | `FUN_0041886b` | `2` | `unity` |

### 5.1 Unity / WSS

`FUN_0041886b`：

```c
url = "wss://" + gateway;
set protocol/header "taomee";
set protocol/header "h5_web_taomee";
send(1001, body);
```

body 由 `FUN_00419fcd(&PTR_DAT_00e69078)` 生成（session/uid/区号/平台/UA）。
2.0.9 的字符串 `unity_app_taomee` / `com.taomee.seer.mobile` 说明平台字段应写
`unity_app_taomee`；官方模板原值为 `unity_webgl_h5`，两者都支持。

### 5.2 Flash

`FUN_0044ae52`：

```c
DAT_00e68fd8 = 1;
// 选服务器列表，FUN_0044b573 连接
set header "!crAckmE4nOthIng:-)";
set header "unknown";
body = hex("000000010000000100000001000...000");  // 0x8ca151，44B
send(1001, body);
```

`0x8c64d9` 的 21 字节常量（`00000015...`）是 cmd `101` 帧，不是登录包；
本仓库保留为 `pack_flash(101, ...)` 的模板/心跳。

### 5.3 1001 响应

`FUN_0041a625`：

```c
if (cmd == 0x3e9 && result < 0x65) {
    DAT_00e6900c = uid;
    DAT_00e68fd0 = 1;       // login success
}
```

`0x65` = 101，是成功码上限；失败码通常 >1000。
登录成功后 `FUN_0061c0e1` 输出 `登录成功[Unity/Flash]`。

## 6. 本仓库的取舍

- HTTP 层：`urllib` + cookie jar，URL/字段/headers 与反编译一致。
- WSS：自实现 RFC6455，按 `taomee`/`h5_web_taomee` 子协议。
- 1001 body：使用官方 508B 模板，字段偏移见 `docs/逆向分析.md`；
  `area_id` 默认 `None`，需要抓包校准。
- Flash body：使用 `0x8ca151` 的 44B 常量，cmd 1001。
- 没有实现：`account.ini` 密码解密、`.ysc` VMProtect、`dzb.txt` 加密。
