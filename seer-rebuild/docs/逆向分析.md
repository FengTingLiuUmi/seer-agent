# 逆向分析：雷小伊脱机日常 2.0.9

> 结论按“观察 / 推断 / 未知”标注。地址均为模块基址 `0x400000` 下的 RVA/VA（本文写 VA）。

## 2. 登录链路

### 2.1 账号密码（Flash / 直登）

2.0.9 字符串（`re/dumps/lx209c_strings` 可复现）：

| VA | 字符串 |
|---|---|
| `0x8c5a40` | `http://account-co.61.com/index.php?r=userIdentity/authenticate&callback=jQuery19008830978978300397_` |
| `0x8c59ea` | `&game=02&tad=none&_=` |
| `0x8c59ff` | `&rememberPwd=true&vericode=` |
| `0x8c5a1b` | `&rememberAcc=false&passwd=` |
| `0x8c5a36` | `&account=` |
| `0x8c5aac` | `result` |
| `0x8c5ab5` | `err_desc` |
| `0x8c5abe` | `data.uid` |
| `0x8c5ac7` | `data.session` |

2.0.7 反编译进一步确认（`re/tools/ghidra_auth.log`，UTF-16LE）：

```c
url = "http://account-co.61.com/index.php?r=userIdentity/authenticate&callback=jQuery..."
    + "&account=" + account
    + "&rememberAcc=false&passwd=" + md5(password)
    + "&rememberPwd=true&vericode=" + ...
    + "&game=02&tad=none&_=" + random;
// 解析 result/err_desc；result==0 时取 data.uid / data.session
```

**推断**：`passwd` 是 32 位小写 MD5；`session` 是 16 字节二进制（以 hex 字符串返回）。
`account.ini` 里的 `pass=` 不是 MD5，长度 12/18 hex，说明 2.0.9 本地存的是加密后的密码，
运行时解密后再算 MD5（未在本次静态分析中定位解密函数）。

### 2.4 登录包

H5（Unity）：cmd `1001`，body 为 508B 模板：

| 偏移 | 内容 | 证据 |
|---:|---|---|
| `0x00` | 16B session | 官方 H5 模板 + `seer-auto` 实测 |
| `0x52` | u16 端口/网关 | 模板 `0x0BBA`=3002 |
| `0x54` | u32 区号 | 模板 `1`；2.0.9 日志有 `[2514]区` |
| `0x58` | `PC` | 模板 |
| `0x6c` | u32 `10101` | 模板 |
| `0x7c` | `unity_webgl_h5` / `unity_app_taomee` | 模板 + 2.0.9 字符串 `0x8ca1b3` |
| `0x98` | `com.taomee.seer.mobile` | 模板 + 2.0.9 字符串 `0x8ca1c4` |
| `0x178` | UA（`Edge157.0.0.0`） | 模板 |

Flash：`FUN_0044ae52`（`DAT_00e68fd8=1`）先连服务器列表，然后：

```c
local_18 = 0x8ca151;                 // "000000010000000100000001000...000"
local_1c = FUN_00419fcd(&local_18);  // hex -> 44 字节
FUN_00418e9b(0x3e9, &local_1c);      // cmd 1001 + 44B body
```

`0x8c64d9` 的 21 字节常量是另一条 cmd `101` 帧（17B 头 + 4B body）；
它不是 Flash 登录包，作为心跳/探测模板保留。

**推断**：H5 与 Flash 都是 17B 头，只差 version（`0x31` vs `0x00`）；
Flash 的 44B body 是固定握手，session 可能放在 HTTP/自定义头里。
**未知**：Flash 包是否有加密/校验；本次未定位到加密函数。

### 2.5 官方 H5 抓包校准

`seer-auto/cmdlog2.jsonl` 保留了一次真实官方 H5 会话（uid ACCOUNT）：

```
1001 uid=ACCOUNT body=79B
ee243c64c5603e9c190743ee94d2cb80  // 16B session
6835                              // u16 serverid = 26677
000...                            // 到 79B
```

同一抓包还包含 `105/109/111` 登录网关帧、`1002` 心跳，以及
`2404/2405/2408/2419` 等战斗/日常命令，可作为 `client.py` / `daily.py` 的校准样本。
**观察**：这些真实帧的 version 是 `0x3e`，而 2.0.7 反编译/旧文档写 `0x31`；
`parse_h5` 现在两者都接受，`pack_h5` 默认 `0x31`、可用 `version=0x3e` 覆盖。
本仓库 `captures.py` 的 `compact_1001_body()` 复刻了这个 79B 形式。

**注意**：2.0.9 的 508B 模板与官方 H5 的 79B 抓包不是同一版本；
`build_h5_login_body()` 保留 508B 模板，`captures.compact_1001_body()` 保留 79B 抓包形式。

关键结论（2026-11 已用 seerapi `factor`/`factor_design` + 本地 `Fragments.ini` 重新校准）：

- 因子关战斗复用标准 PVE BOSS 战链路（42396/2404/2405/2506），
  不是另一套“因子”专用命令。
- 切阵容必须用**个体 catch_time**（2304 的 body），不是 species；
  catch_time 需先 `43706` 读背包后按 species 反查（`pets.read_bag`）。
- 数据模型：目标精灵 → `factor`(factor_id) → `factor_design`(design_id) →
  `{time_value, progress_value, fail_times}` 三个 46046 forever 键 +
  easy/normal/hard 各 5 个 `task.boss_pet.id`。
  - 谜之英雄因子（factor 2400532, design 225）：BOSS = 4539/4330/4137/4845/4848，
    forever progress=302126 / time=302127 / fail=302124。
  - 灵巢之主·索杰德尔因子（factor 2400338, design 141）：BOSS = 4569/4568/4594/4597/4599，
    forever progress=209678 / time=209679 / fail=209676。
- `45543` 是**图鉴/精灵收集进度**（`[id][ts][flag][progress]`，progress 0–100），
  **不是**因子关卡列表；同精灵可按时段出现多条（如几米 3582 有 100 与 1）。
- `Fragments.ini`（GBK）是本地因子表：`[factor_id] → MonsterID/Name/MoveID/effectId`。

**未校准**：42396 的“关卡 id ↔ 第几关”完整映射、以及多回合逐回合战斗循环
的回合切换确认，尚未用真实账号端到端校准；当前 `factor_runner.run()` 按

### 2.7 实机测试（小号 ACCOUNT）

用小号 ACCOUNT（仅 1 只正式伊优 + 1 只待命劳加德）实机验证结果：

|---|---|---|
| 登录 + 连接（Unity TCP） | ✅ | 正常拿到 1001 并握手 |
| `43706` 读背包 | ✅ | 返回 `[count=1][species=4 伊优]` |
| `45543` 关卡列表 | ✅ | `[0,999]` 返回 125 项；`[1000,1999]` 返回 0 项（本号条目 <1000） |
| `46046` 进度 `[0x4a0c6,0x4a0c7,0x4a0c4,0x1ece9]` | ✅ 返回 `[0,0,0,0]` | 本例 forever 全 0（未开工或该 ids 非本号进度） |

且 2001 进入因子界面的前置状态尚未抓全。要真打，需要：① 该号在雷小伊里
跑一次因子并抓 `42396/2404` 拿正确关卡 id；② 或提供正确关卡 id 映射。

### 2.8 官方 Unity 端「进因子关」流程（unity_mzyx，2026-11 解决关卡 id）

用户录了官方 Unity 端打谜之英雄第 1 关：登录→图鉴→搜索谜之→选谜之英雄→
进入关卡→选第 1 关→进入战斗。明文解析结果（关键命令）：

```
46046  [125631, 302126, 302127, 302124, 302125]   # 读谜之英雄 forever 状态
46089  [1, 4848]                                   # 查因子详情（4848=谜之英雄）
41284  [225, 1]     # 进入因子关：body=[design_id][stage_index]
41282  [225, 1]     # 开始因子战斗：body=[design_id][stage_index]
2441   [0,3,3,3,15,18]  # 战斗加载进度（LOAD_PERCENT）
（之后 S2C cmd=0 战斗观测帧 → 41129 结算）
```

**关键结论：官方 Unity 端打因子根本不用 `42396` 的「关卡 id」**，而是
`41284/41282` + `[design_id][第几关]`。`42396` 是雷小伊 7 月旧链路
（关卡 id=0x6f=111，属沙罗摩奥因子）。design_id 就在 `factor_design.id`：
谜之英雄=225、灵巢之主=141、沙罗摩奥=267。

`factor_runner.py` 已改为默认走官方端 `41284/41282` 链路（`design_id + stage`）。

出招循环（unity_yz_battle.pcapng，戟决先锋 design=228 通关前 2 关实证）：

```
41284/41282 [228][1] → 43706 → 2441[24→100] → 2404 准备
  → 2405[31505] 出招 → 2407[62ef6f18] 切换 → 2405[19314] 出招 → 2407[6af9cf5e] 切换 → 2405[19932]
  → 2506 战斗结束 → 43706
```

即：`2404` 之后按「`2405` 出招 → `2407` 换精灵」往复，直到 2506。
`2407` body = 个体 catch_time；`2405` body = 技能 id。代码 `factor.battle_loop_steps()`。

`.cjpt` 是“六界/克罗”等辅助精灵的引用 section，字段更少。

本仓库的 `cjc.py` 保留重复 section，按 `循环技能/循环次数` 轮转；
`出招条件/比较方式/比较值` 支持“对方强化总和 / 我方血量 / 对方血量 / 回合”。

### 3.2 `.cjcy` 容器

`seer_cfg/script/*.cjcy` 是十六进制文本。解码后：

```
[u32 compressed_size][u32 ???][u32 uncompressed_size]
[zlib stream]
  -> [u32 name_len=25][u32 7][u32 dzb_size][u32 dzb_size]
     "dzb.txt" + 32 hex MD5 + encrypted body
```

例：`5.29量子回廊静态基准v1.3.cjcy` 解码后 zlib 偏移 12，解出 56,580B；
其中 `dzb.txt` 39,304B 与磁盘上的 `method/*/dzb.txt` 完全同构。
**未知**：`dzb.txt` 的加密算法；本次未定位到解密函数。

### 3.3 `.ysc` / VMProtect

`Script/*.ysc` 头部 `00 00 01 44 8a 92 3d ca...`，高熵，无 zlib 头。
镜像 `0x8d25f9` 有字符串 `.ysc` + `VMProtect begin`，说明 `.ysc` 走 VMProtect 虚拟化/加密。
**结论**：不做脱壳/解密；本仓库用可读的 Python/JSON 脚本复刻“日常/对战方案”的行为。
